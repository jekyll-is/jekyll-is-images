# jekyll-is-images

Jekyll-плагин для работы с картинками и галереями.

## Концепция

Основная идея плагина: расширенная обработка изображений _на базе стандартного синтаксиса Markdown_. Более того, парсинг
осуществляется стандартными же средствами, т.е. не требует дополнительных ресурсов относительно обычного пайплайна, а затем
плагин переинтерпретирует расширенный набор атрибутов, встраиваясь внутрь процесса Kramdown.

У этого есть и обратная сторона: *плагин работает строго поверх Kramdown*, если вы используете другой markdown-конвертер,
бо́льшая часть возможностей будет недоступна.

### Функциональность

1. Ресайз, конвертация и прочая оптимизация изображений.

2. Оборачивание изображений в `figure` с расширенными возможностями стилизации, включая «умные» плавающие позиции, добавление
   заголовков, обтекание по рисунку (исходя из прозрачных областей).

3. Формирование галерей изображений.

4. Формирование Open Graph изображений для предпросмотра в социальных сетях.

### Кэширование

Сконвертированные изображения кэшируются в отдельном каталоге, который можно сохранять, например, между сеансами в GitHub Actions
и других системах сборки. Таким образом при изменении одной страницы не потребуется перегенерировать изображения для всего сайта.

## Подключение

### Системные требования

+ Работа плагина рассчитана и проверялась **только под Linux**. Скорее всего, под другими unix-like системами тоже будет работать.

+ Внешняя зависимость, т.е. не устанавливающаяся автоматически через `bundle install` одна — **ImageMagick** 7-й версии.

### Непосредственное подключение

Плагин подключается в Jekyll стандартными средствами: через группу `:jekyll_plugins` в `Gemfile` и/или через секцию `plugins`
в `_config.yml`. В принципе этого достаточно, но есть нюансы.

Для более корректного подключения CSS и JS будет лучше явно прописать их загрузку в шаблонах, если есть такая возможность. Поскольку
имена скриптов и CSS включают версии и некоторые другие данные, лучше воспользоваться liquid-тегами:

    {% is_images_css %}
    {% is_images_js %}

или все вместе одной строкой:

    {% is_images_stuff %}

А автоматическое подключение убрать, выставив параметр в `_config.yml`:

    is_images:
      disable_auto_stuff: true

### Markdown-функции

Чтобы заработали основные функции, завязанные на перехвате markdown-разметки, нужно также включить кастомный markdown-парсер в конфиге.

    markdown: kramdown
    kramdown:
      input: ISKram

Он унаследован от стандартного `Kramdown`, используемого в Jekyll по умолчанию, и во всем остальном его поведение не модифицировано.

## Использование

### Markdown-разметка

#### Изображения

Используется стандартный синтаксис `![Alt text](source){: attributes }`. Однако набор атрибутов не просто передается в HTML,
а интерпретируется для преобразований. При этом привычные `#id`, `.class_name`, `style="border:none;"` работают так же, как
и в базовом Kramdown.

Важный момент относительно `source`, т.е. того, что в разметке располагается в круглых скобках и попадает в атрибут `src` тега `<img ...>`:
если источник картинки начинается с `/`, обработка *не производится*, т.е. тег `<img ...>` формируется исключительно *стандартными*
средствами. Если там указана внешняя ссылка, т.е. начинается с `http://` или `https://`, картинка по возможности *скачивается в кэш*
и обрабатывается.

При этом имеется специальный атрибут:

+ `is-image="‹value›"`

  `true` (а также `1`, `yes`, `+`) или `false` (`0`, `no`, `-`). При установке в `false`, картинка не обрабатывается и теги формируются
  штатными средствами. Установка в `true` для картинок, начинающихся с `/` не включает обработку, но позволяет картинке попасть в галерею.
  В целом атрибут не рекомендуется к использованию, поскольку логика может быть неочевидной.

Расширенные атрибуты:

+ `format="webp|avif|png|jpeg|tiff|..."`

  Целевой формат. Как правило, не требует указания, вместо этого настраивается в конфигурации для всего сайта. См. ниже.

+ `href="‹url›|none|view"`

  Ссылка. Т.е. формируется конструкция вида `<a href="..."><img ...></a>`. При этом, если параметр не указан, по умолчанию
  трактуется как `view` — то есть локальная ссылка на бо́льшую версию изображения.

+ `title="‹string›"`

  Формирует атрибут `title` тега `<a>` (или `<span>`, если `href="none"`). По умолчанию берется текст из `alt`, т.е. то, что
  пишется в квадратных скобках.

+ `width="‹int›"`

  Ширина картинки, определяет как ширину тега `<img>`, так и (совместно с параметрами `height`, `fit` и `scale`) размер
  преобразованного изображения.

+ `height="‹int›"`

  Высота картинки.

+ `fit="contain|cover|fill|scale-down|none"`

  Режим заполнения. Соответствует значениям CSS-свойства `object-fit`, влияет на ресайз картинки. По умолчанию — `contain`.

+ `scale="‹float›"`

  Коэффициент, на который умножаются `width` и `height` для ресайза. Не оказывает влияние на размеры тега `<img>`. Может быть,
  например, использовано для увеличения картики по `:hover` (передается в CSS-переменную `--is-images-scale`).

+ `crop="‹int›x‹int›+‹int›+‹int›"`

  Позволяет выбрать область исходной картинки, которая будет взята. Формат: «`WxH+X+Y`».

+ `salt="‹string›"`

  Соль хэша. Позволяет перегенерировать результирующую картинку без изменения значащих параметров.

+ `lazy`

  Флаг (без значения). Добавляет `loading="lazy"` тегу `<img>`.

+ Дополнительные атрибуты формата.

  Можно задать дополнительные параметры конвертации в целевой формат, типа `webp-progressive="true"`. Эти параметры зависят
  от собственно параметра и их набор можно найти в документации по ImageMagick. Однако рекомендуется такие параметры задавать
  не в тексте, а в специальной секции `_config.yml`.

+ Атрибуты изображения просмотра:

  + `view-format`,
  + `view-width`,
  + `view-height`,
  + `view-fit`,
  + `view-crop`.

  Влияют на картинку для просмотра по клику.

+ Атрибуты `data-*`

  Передаются в тег `<img>` «как есть».

#### Иллюстрации

Если картинка находится на строке, отделенной сверху и снизу пустыми строками, в стандартном Kramdown формируется конструкция вида
`<p><img ...></p>`. Плагин заменяет ее конструкцией вида `<figure><img ...></figure>` и дополнительно интерпретирует следующие
атрибуты и флаги:

+ `caption="‹string›"` или флаг `caption`

  Добавляет тег `<figcaption>`, в форме флага содержимое этого тега берется из `alt`.

+ `caption-position="top|bottom"`

  Определяет размещение тега `<figcaption>` — сверху или снизу от картинки.

+ `right` или `left`

  Задает «умное» плавающее положение. В целом соответствует CSS `float:right;` и `float:left;`, но обвязано некоторыми дополнениями —
  рекомендуется использовать именно эти флаги, а не простое указание свойства в `style="..."`.

+ `shape`

  Формирует обтекание по картинке. Будет работать на форматах с прозрачностью: PNG, WebP и SVG. Работает только для плавающих иллюстраций.

+ `up="‹int›"` и `shift=‹int›`

  Позволяет сдвинуть картинку относительно нормального положения. `up` сдвигает вверх, а `shift` — вправо или влево, в зависимости
  от положения — всегда наружу, как бы на поля. Работает только для плавающих иллюстраций.

Важный момент: атрибуты и флаги могут быть указаны как в IAL блока, так и в IAL инлайнового элемента, т.е. картинки.

<pre>
{: ‹атрибуты блока› }
![Alt text](source){: ‹атрибуты изображения› }

</pre>

Плагин автоматически перенесет атрибуты изображения, относящиеся к блоку в атрибуты блока. Более того, _все_ классы и все флаги, кроме `lazy`,
также будут перенесены в `<figure>`. Значения `style` будут применены раздельно. Это следует иметь в виду при разработке своих CSS, работающих
с плагином. Такая логика введена ради того, чтобы описывать простые иллюстрации одной строкой (т.е. без отдельного прописывания атрибутов блока).

#### Галереи

Если в один блок собрать несколько изображений, будет сформирована галерея. Галерея может быть представлена в разных режимах, на данный
момент таких доступно два: `grid` и `slides`. Режимы можно применить к одной и той же галерее, тогда будет показываться переключатель.

Помимо вышеупомянутых `caption` и `caption-position` к галереям применимо свойство режимов:

+ `modes="‹list›"`

  Определяет набор и _порядок_ режимов, применяемых к галерее.

Кроме того, галерея переопределяет некоторые свойства входящих в нее картинок. Делается это посредством соответствующих свойств с префиксом,
зависящим от режима.

|                    | `grid`                  | `slides`                 |
|--------------------|-------------------------|--------------------------|
| `format`           | `cell-format`           | `slide-format`           |
| `width`            | `cell-width`            | `slide-width`            |
| `height`           | `cell-height`           | `slide-height`           |
| `scale`            | `cell-scale`            | `slide-scale`            |
| `fit`              | `cell-fit`              | `slide-fit`              |
| `crop`             | `cell-crop`             | `slide-crop`             |
| `lazy`             | `cell-lazy`             | `slide-lazy`             |
| `caption-position` | `cell-caption-position` | `slide-caption-position` |

Да, элементы галереи также оборачиваются в `<figure>` и к ним применимы свойства `caption` — для каждого элемента свое значение, и `caption-position` —
значение задается на уровне галереи. Как можно видеть по префиксам, для разных режимов галереи свойства ее элементов задаются независимо.

#### Liquid-теги

Если по каким-то причинам вы не хотите или не можете использовать кастомный markdown-парсер (например, уже используете какой-то другой вместо
стандартного `Kramdown`), описанный выше функционал доступен и через liquid-теги.

    {% image src="‹source›" alt="‹alt text›" ‹атрибуты› %}

Важный момент: liquid-разметка ничего не знает об окружении тега. Соответственно, чтобы определить, что картинка требует оборачивания в `<figure>`,
нам нужно указать это явно — флагом `figure` в атрибутах. Также атрибуты `src` и `alt` необходимо указывать стандартным образом. В остальном
функциональность идентична описанному выше.

Галереи формируются при помощи liquid-блока:

    {% gallery ‹атрибуты› %}
      {% image src="image1.jpg" alt="Первая картинка" %}
      {% image src="image2.jpg" alt="Вторая картинка" %}
         . . . . .
      {% image src="imageN.jpg" alt="N-ная картинка" %}
    {% endgallery %}

Внутри окружения `{% gallery %}` допустимо формирование содержания через `{% if %}`, `{% for %}`, `{% include %}` и так далее,
при этом все получившееся содержимое, кроме тегов `{% image %}`, игнорируется.

#### Предпросмотр в соцсетях

Данный плагин встраивается в стандартное определение картинки для предпросмотра, которое в Jekyll определяется свойством `image`
во front-matter страницы. Наш плагин берет свойство `image`, преобразует изображение по формату и размерам, затем накладывает
плашки с заголовком страницы, датой и названием сайта.

Все это настраивается — см. далее.

### Конфигурация

#### Общие принципы

Настройки получаются каскадно (в порядке увеличения приоритета):

+ Значения по умолчанию.

+ Значения из `_config.yml` (из секции `is_images`).

+ Значения из front-matter текущей страницы (из секции `is_images`).

+ Значения, непосредственно указанные в атрибутах.

#### Пример конфига

    is_images:

      abort_on_error: true
      target_prefix: img
      cache_path: .is-images-cache
      cache_digits: 8

      disable_auto_stuff: true

      default_link: view
      caption_position: bottom

      view:
        width: 1800
        height: 1200

      gallery:
        caption_position: top
        modes: slides,grid

      grid:
        width: 200
        height: 200
        lazy: true

      slides:
        width: 800
        height: 600
        lazy: true

      formats:
        svg: svg
        jpeg: avif
        avif: avif
        default: webp

      options:
        jpeg:
          quality: 90
        webp:
          quality: 80
          method: 6
          progressive: true
          alpha_compression: 1
        avif:
          quality: 70
          speed: 1
          chroma_subsampling: '4:2:0'

      seo_image:
        format: webp
        width: 1200
        height: 630
        overlay:
          width: 1150
          bottom: 150
          top: 50
          padding: 25
          background: '#6669'
          foreground: '#EEEE'
        font:
          caption: PT-Sans-Caption
          date: PT-Mono
          date_size: 24
          site: PT-Sans-Narrow
        date_format: '%Y/%m/%d'
        site: Мой блог

      min_text_width: 200
      max_text_width: 1920

В основном в этом примере значения по умолчанию, так что нет нужды его копировать целиком в `_config.yml`. Пример дан для понимания общей структуры конфигурации.

#### Глобальные настройки

+ `target_prefix`

  Префикс пути к изображениям на сайте, по умолчанию — `img`. То есть, дефолтный путь выглядит как `/img/‹хеш-путь›.‹формат›`.

+ `cache_digits`

  Количество символов в последней части хеш-пути. Вообще, используется алгоритм хеширования SHA256, который дает довольно длинную последовательность.
  На большинстве сайтов ее можно смело обрезать без особого риска появления коллизий. По умолчанию `8`, т.е. пути выглядят как-то так:
  `/img/01/23/456789ab.webp` — каталогов всегда два и оба состоят из двух символов, а вот последнюю часть — «имя файла» — можно увеличить или укоротить
  благодаря этой настройке.

+ `cache_path`

  Каталог с кэшем изображений. Располагается внутри каталога проекта, по умолчанию `.is-images-cache`. Рекомендуется исключить данный каталог из репозитория
  посредством `.gitignore`, но настроить его промежуточное сохранение между сборками в GitHub Actions. Менять значение по умолчанию особого смысла нет.

+ `abort_on_error`

  `true` или `false`. Должна ли прерываться сборка при возникновении ошибки. По умолчанию `true`.

+ `disable_auto_stuff`

  `true` или `false`. Позволяет отключить автоматическую вставку загрузки CSS и JS, чтобы вписать ее аккуратно в шаблоны страниц. По умолчанию пусто,
  т.е. интерпретируется как `false`.

+ `disabled`

  `true` отключает плагин полностью.

#### Дефолтное поведение

+ `default_link`

  Определяет поведение в случае, когда не указан атрибут `href` у изображения. Варианты `0`, `false`, `no`, `none` означают, что никакой ссылки
  генерироваться не будет; варианты `1`, `true`, `yes`, `auto` и `view` — что будет генерироваться ссылка на бо́льшую версию изображения.

+ Подраздел `view`

  Содержит параметры `format`, `width`, `height`, `fit` и `crop`, задающие умолчания для соответствующих атрибутов `view-*`. И это рекомендованное
  использование — задать эти параметры для всего сайта сразу, а не писать в атрибутах, кроме `crop`, который вряд ли будет общим для всех изображений,
  и `format` — когда не задан, берется тот же формат, что и малого изображения на странице, который определяется автоматически, о чем см. ниже.

+ `caption_position`

  `top` или `bottom`. По умолчанию — `bottom`. Определяет положение подписей _к одиночным картинкам_.

##### Галереи

+ Подраздел `gallery`:

  + `caption_position` — определяет положение заголовков _галерей_.

  + `modes`

    Список режимов, определяет состав и порядок режимов галерей. По умолчанию — `grid,slides`. В большинстве случаев все-таки режимы будут указываться
    для каждой галереи отдельно, но если ничего не указано, будет использоваться это значение.

+ Подразделы режимов (сейчас это `grid` и `slides`).

  + Параметры `format`, `width`, `height`, `scale`, `fit`, `crop` и `lazy`, задающие умолчания для префиксных значений (`cell-*` и `slide-*` соответственно).

  + Параметр `label` — определяет название режима в переключателе.

#### Параметры конвертации

+ Подраздел `formats`

  Маппинг форматов: из какого исходного в какой конвертируем. По умолчанию схема такова:

      formats:
        svg: svg
        jpeg: avif
        avif: avif
        default: webp

  Предполагается, что фотографии мы пережимаем в avif, что дает для них максимальную компактность, а, например, скриншоты или картинки в прозрачностью
  в формате PNG (а также все прочие форматы не попавшие под явное правило) преобразуем в WebP с сохранением четких границ и прозрачности.
  Векторные изображения не преобразуем в другие форматы.

+ Подраздел `options`

  Дополнительные параметры конвертации, передаваемые в ImageMagick. Эти параметры зависят от целевого формата, соответственно разбиты по подразделам.
  По умолчанию так:

      options:
        jpeg:
          quality: 90
        webp:
          quality: 80
          method: 6
          progressive: true
          alpha_compression: 1
        avif:
          quality: 70
          speed: 1
          chroma_subsampling: '4:2:0'

  Здесь нужно отметить, что `quality` передается в ImageMagick как общий параметр `-quality`, остальные передаются через `-defines` путем преобразования
  и склейки, например `webp:alpha-compression=1`, то есть приводятся к правильному формату. Отдельно нужно заметить, что для формата `avif` автоматически
  подставляется префикс `heic:`, а не `avif:`... В целом, большинству пользователей изменять эти параметры не потребуется.

#### Превью для соцсетей

Настройки находятся в подразделе `seo_image`.

+ `format`

  По умолчанию `webp`, поскольку более компактные форматы, даже если они поддерживаются браузерами, не поддерживаются соцсетями.

+ `crop`

  В привычном формате, понимаемом ImageMagick — «`WxH+X+Y`». Позволяет выбрать фрагмент исходной картинки.

+ `width` и `height`

  Разрешение картинки, по умолчанию `1200` и `630`. При этом картинка подгоняется под эти размеры всегда, даже если исходная картинка меньше, поскольку
  соцсети просто не примут слишком маленькую картинку.

+ Подраздел `overlay`

  Определяет основные параметры текста и подложки, накладываемых на изображение. Подложка состоит из двух прямоугольников: нижний для заголовка, верхний —
  для даты и названия сайта.

  + `width` — определяет общую для обоих частей подложки ширину.

  + `bottom` — определяет высоту нижней части подложки.

  + `top` — определяет высоту верхней части подложки.

  + `padding` — значение отступа, которое используется в нескольких местах:

    + Отступ от верхнего края картинки до верхнего края верхней части подложки.
    + Отступ от нижнего края картинки до нижнего края нижней части подложки.
    + Отступы справа и слева внутри верхней части подложки до текста.
    + Отступы со всех сторон внутри нижней части подложки до текста заголовка. Тут нужно заметить, что отступ здесь определяет _доступное_ для
      размещения заголовка место, тогда как его _актуальное_ размещение определяется внутренними алгоритмами ImageMagick.

  + `background` — определяет цвет подложки, предпочтительно с прозрачностью. По умолчанию `#6669` (специфический для IM RGBA-формат). Можно использовать
    любую строку, которую поймёт ImageMagick.

  + `foreground` — определяет цвет текста. По умолчанию `#EEEE`.

+ Подраздел `font`

  Определяет используемые шрифты.

  + `caption` — шрифт заголовка.

  + `date` — шрифт даты.

  + `date_size` — размер шрифта даты.

  + `site` — шрифт названия сайта. Если не указан, используется шрифт из `date`.

  + `site_size` — размер шрифта названия сайта. Если не указан, используется размер из `date_size`.

+ `date_format`

  Формат даты. По умолчанию — «`%Y/%m/%d`».

+ `caption`

  Позволяет использовать произвольную строку вместо заголовка страницы.

+ `date`

  Позволяет использовать _произвольную строку_ вместо даты.

+ `site`

  Позволяет использовать произвольную строку вместо названия сайта.

#### Специальные параметры

Плавающие иллюстрации устроены таким образом, чтобы отключать «плавучесть», когда текст становится слишком узким. Для управления этим
поведением используется два специальных параметра.

+ `min_text_width`

  Размер текста, который _должен остаться_ справа или слева от картинки. То есть, если (`min_text_width` + ширина картинки) превышает
  ширину контейнера, картинка перестает быть плавающей. По умолчанию — `200`.

+ `max_text_width`

  Механизм включения/выключения «плавучести» порождает довольно громоздкие CSS-конструкции, чтобы ограничить их генерацию только нужными,
  стоит указать в этом параметре максимальную ширину контейнера, возможную у вас на сайте. По умолчанию — `1920`, можно делать как больше,
  так и меньше.
