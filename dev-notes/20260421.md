## Концепция (финализировано)

**Входные точки:**
- Markdown `![alt](path)` + IAL `{: params }` → перехват через `is-kramdown-hooked`
- Legacy `![alt](path)` без IAL → опциональная обработка по глобальным дефолтам

**Правила маршрутизации:**
- `path` в `./_src/**` → полная обработка (конвертация, resize, форматы, атрибуты)
- `path` в стандартных assets → только IAL-атрибуты (классы, стили, title)
- Внешний URL → pass-through с IAL-атрибутами

**Типы контента:**
- Обычные изображения → конвертация в настраиваемые форматы (WebP/AVIF/etc), resize, `<img>` или `<picture>`
- SVG → манипуляция width/height/viewBox, shape-outside через CSS
- Панорамы (explicit IAL) → multires tiles для Pannellum
- Галереи (future) → группировка, grid разметка

**Кэширование:**
- Локальная директория (настраиваемо, по умолчанию `.jekyll-is-cache/`)
- Инвалидация по хэшу исходника + параметрам обработки
- GitHub Actions кэширует директорию отдельно

## Планирование

### Этап 0: Инфраструктура гема
- Структура: стандартный Ruby gem с `lib/`, `spec/`, `exe/`
- Зависимости: `is-kramdown-hooked`, `is-ial-parser`, `mini_magick` (или `rmagick`), `nokogiri` (для HTML манипуляций)
- Dev-зависимости: `rspec`, `rubocop`, `simplecov`
- CI: GitHub Actions с матрицей Ruby/Jekyll версий

### Этап 1: Конфигурация и валидация
```yaml
# _config.yml
jekyll-is-images:
  src_dir: "_src"                    # исходники для обработки
  cache_dir: ".jekyll-is-cache"      # локальный кэш
  output_dir: "assets/generated"     # относительно _site
  
  formats:                           # глобальные целевые форматы
    - webp
    - avif
  
  quality:                           # качество per format
    webp: 85
    avif: 80
  
  sizes:                             # дефолтные размеры
    default: "800w"
  
  legacy_processing: false           # обрабатывать ![alt](url) без IAL
  
  svg:
    adjust_dimensions: true        # манипулировать width/height/viewBox
  
  panorama:
    tile_size: 512
    max_level: auto
```

### Этап 2: Pipeline обработки

**2.1 Hook регистрация**
```ruby
# Подписка на post_parse хук is-kramdown-hooked
ISKramdownHooked.register_post_parse_hook do |parser|
  JekyllISImages::Processor.new(parser, site_config).process!
end
```

**2.2 Разбор IAL**
- Делегируем `is-ial-parser`
- Валидные ключи: `format`, `quality`, `width`, `height`, `class`, `style`, `title`, `panorama`, `gallery`, `shape`, `inline`

**2.3 Маршрутизация**
```ruby
case resolve_path(src)
when :src_dir     → FullProcessor
when :asset_dir   → AttributeOnlyProcessor  
when :external    → ExternalProcessor
end
```

**2.4 FullProcessor (для `./_src`)**
```
1. Вычислить cache_key = hash(file_content + processing_params)
2. Если cache_key существует в cache_dir → использовать закэшированные файлы
3. Иначе:
   a. Для растров: конвертировать в целевые форматы, resize
   b. Для SVG: манипулировать атрибутами, сохранить копию
   c. Для панорам: нарезать multires tiles (Pannellum generate.py или аналог)
   d. Сохранить в cache_dir, записать манифест
4. Скопировать из cache_dir в _site/output_dir
5. Сгенерировать HTML (img / picture / panorama div)
```

**2.5 Кэш-инвалидация**
- Манифест: JSON с mapping `cache_key → [generated_files]`
- При изменении исходника или параметров — новый cache_key, старые записи помечаются orphaned
- Cleanup: удалять orphaned файлы старше N дней (или по команде)

### Этап 3: HTML генерация

**Обычное изображение:**
```html
<!-- Если один формат -->
<img src="/assets/generated/path/image.webp" 
     alt="alt" 
     class="__image user-class" 
     style="shape-outside:url(...)" 
     title="title">

<!-- Если несколько форматов -->
<picture>
  <source srcset="/assets/generated/path/image.avif" type="image/avif">
  <source srcset="/assets/generated/path/image.webp" type="image/webp">
  <img src="/assets/generated/path/image.jpg" alt="alt" ...>
</picture>
```

**SVG:**
```html
<img src="/assets/generated/path/image.svg" 
     alt="alt" 
     class="__image" 
     style="shape-outside:url(/assets/generated/path/image.svg)" ...>
```

**Панорама (Pannellum multires):**
```html
<div id="panorama-1" class="pannellum"></div>
<script>
pannellum.viewer('panorama-1', {
    "type": "multires",
    "multiRes": {
        "basePath": "/assets/generated/path/panorama",
        "path": "/%l/%s%y_%x",
        "fallbackPath": "/fallback/%s",
        "extension": "jpg",
        "tileResolution": 512,
        "maxLevel": 4,
        "cubeResolution": 2496
    }
});
</script>
```

### Этап 4: Интеграция Pannellum multires

**Вариант A:** Вызов `generate.py` из Pannellum
- Требует Python + Pillow в окружении
- GitHub Actions: `actions/setup-python` + `pip install Pillow`

**Вариант B:** Реализация на Ruby через ImageMagick/GraphicsMagick
- Более чистый стек, но нужно реализовать нарезку cubemap/equirectangular tiles
- Сложнее поддерживать совместимость с Pannellum

**Рекомендация:** Начать с Варианта A (вызов `generate.py`), абстрагировав через адаптер. В будущем можно добавить нативную реализацию.

### Этап 5: Галереи (future)

IAL-группировка:
```markdown
![img1](a.jpg){: gallery="trip" cols=3 }
![img2](b.jpg){: gallery="trip" }
![img3](c.jpg){: gallery="trip" }
```

Генерация grid-разметки + lazy-load.

## Открытые вопросы для решения

| Вопрос | Варианты | Рекомендация |
|--------|----------|--------------|
| ImageMagick vs GraphicsMagick vs libvips | mini_magick (ImageMagick), ruby-vips | mini_magick для начала, проще в GitHub Actions |
| Pannellum multires: Python или Ruby | Вызов generate.py / нативная реализация | Адаптер для generate.py |
| Кэш: файловый или SQLite | JSON манифест / SQLite / PStore | JSON манифест, проще отлаживать |
| Формат манифеста | JSON / YAML / MessagePack | JSON |
| SVG resize: парсинг XML или regex | Nokogiri / Rexml / regex | Nokogiri, надёжнее |
