## Выяснили (зафиксировано)

### Архитектура плагина
- **Гем**: отдельный публикуемый gem под LGPLv3, чистый Ruby
- **Зависимости**: `is-kramdown-hooked`, `is-ial-parser`, `mini_magick` (ImageMagick), `nokogiri`
- **Входные точки**:
  - Markdown `![alt](path){: params }` → перехват через `is-kramdown-hooked` post_parse hook, работа с AST
  - Front-matter → отдельный механизм (способ уточняется)
  - Legacy `![alt](path)` без IAL → опциональная обработка по глобальным дефолтам (`legacy_processing: false/true`)

### Маршрутизация исходников
| Расположение | Обработка |
|-------------|-----------|
| `./_src/**` (настраиваемо) | Полная обработка: crop, resize, конвертация форматов, атрибуты |
| Стандартные Jekyll assets | Только IAL-атрибуты (классы, стили, title), без трансформации файлов |
| Внешние URL | Pass-through с IAL-атрибутами, без модификации контента |

### Обработка изображений
- **Форматы**: WebP, AVIF, исходный (настраиваемо глобально и per-image через IAL)
- **Resize**: одно целевое разрешение на начальном этапе, srcset — future
- **Crop**: синтаксис ImageMagick `WIDTHxHEIGHT+OffsetX+OffsetY`, применяется перед resize
- **SVG**: манипуляция атрибутами `width`, `height`, `viewBox` внутри файла; поддержка `shape-outside` через CSS `url()` к внешнему SVG
- **Кэширование**: локальная директория (настраиваемо, дефолт `.jekyll-is-cache/`), ключ = хэш(содержимое файла + параметры обработки: crop, размер, формат, качество); GitHub Actions кэширует директорию отдельно

### HTML-генерация
- **Простые случаи** (`<img>`): модифицированный `:img` в AST, стандартный рендеринг с enriched attributes
- **Сложные случаи** (панорамы, галереи): `:raw` узел с готовым HTML
- **Панорамы**: explicit IAL marker (`{: panorama }`), multires tiles для Pannellum; конвертация в WebP/AVIF если Pannellum поддерживает, иначе исходный формат
- **Галереи**: future, группировка по IAL-ключу

### Конфигурация
- Глобальные дефолты в `_config.yml` в namespace плагина
- Per-image override через IAL для определённого набора параметров (конкретный набор обсуждается)
- Настраиваемые: `src_dir`, `cache_dir`, `output_dir`, `formats`, `quality`, `sizes`, `legacy_processing`, `svg.adjust_dimensions`, `panorama.tile_size`, `panorama.max_level`

## Требуется прояснить

### 1. Механизм front-matter
- **Когда обрабатывать**: `post_init`, `post_read`, `pre_render`, или on-demand через Liquid-фильтр?
- **Какие ключи**: фиксированный набор (`image`, `cover`, `gallery`) или конфигурируемый паттерн?
- **Формат значений**: просто путь (`image: path.jpg`) или структура с параметрами (`image: { src: path.jpg, width: 800 }`)?

### 2. IAL и AST в `is-kramdown-hooked`
- **IAL уже применены?** Приходит ли `:img` с `attr` уже содержащим `crop`, `class`, etc., или IAL висят отдельным `:ial` узлом, и нам нужно самим матчить?
- **Обход AST**: нужен ли нам `is-ial-parser` на этапе AST, или kramdown уже всё распарсил?

### 3. Crop: дефолтное поведение без оффсетов
- `{: crop="400x300" }` без `+OffsetX+OffsetY` — это центрирование (gravity center) или верхний левый угол (`+0+0`)?
- Нужен ли отдельный параметр `crop_gravity`?

### 4. Панорамы: инструментарий multires
- Использовать официальный `generate.py` от Pannellum (Python + Pillow) или искать/делать Ruby-аналог?
- Как обеспечить наличие Python в GitHub Actions — принять как зависимость окружения или контейнеризировать?

### 5. Кэш: инвалидация и cleanup
- **Orphaned файлы**: когда исходник удалён или параметры изменились — удалять сразу, помечать, или периодический cleanup?
- **Манифест**: JSON с mapping `cache_key → [files, metadata]` — структура и способ atomic write?

### 6. Per-image параметры: допустимый набор
- Что можно переопределить через IAL: только `crop`, `width`, `height`, `format`, `quality`? Или также `tile_size`, `panorama.max_level` и т.д.?
- Есть ли параметры, которые глобальные только (например, `cache_dir`, `src_dir`)?

### 7. Обработка в хуке vs отложенная генерация
- Генерировать файлы прямо в `post_parse` (имея только AST и относительные пути)? Или собирать очередь в хуке, а генерировать позже (например, `site.post_read`) когда доступен полный `site` контекст?

### 8. URL-генерация в AST
- В `post_parse` ещё неизвестен финальный `_site` путь. Как подставлять URL: хранить относительный путь в AST и резолвить при рендеринге, или генерировать финальный URL сразу (предполагая структуру `_site`)?

### 9. SVG: какие атрибуты манипулируем
- Только `width`, `height`, `viewBox`? Или также `preserveAspectRatio`?
- Что если в исходном SVG эти атрибуты отсутствуют — добавляем или игнорируем запрос на resize?

### 10. Лицензия и зависимости
- LGPLv3 для чистого Ruby — подтверждено. Но `mini_magick` MIT, `is-kramdown-hooked` и `is-ial-parser` — какие лицензии? Совместимость?
